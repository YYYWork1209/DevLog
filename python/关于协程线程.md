# Python 协程

## 一、协程的基本概念

### 1. 本质定义
协程（Coroutine）是**用户态**的**轻量级并发**机制，它在**单线程**内通过**协作式调度**实现任务的并发执行。

### 2. 核心思想（生活类比：奶茶店）
- **普通函数**：做好一杯奶茶，站在原地傻等封口机完成（CPU等待I/O），白白浪费时间。
- **协程函数**：把奶茶放上封口机，立刻转身去做下一杯，等封口机“叮”一声（I/O完成）再回头处理。

### 3. 三大核心关键字
| 关键字 | 作用 | 通俗解释 |
| :--- | :--- | :--- |
| **`async def`** | 定义一个协程函数 | 告诉Python：“这是一个可以随时暂停的特殊函数”。 |
| **`await`** | 挂起当前协程，交出控制权 | 主动说：“我要等结果，你先去忙别的，有结果了叫我”。 |
| **`asyncio`** | 协程调度库（事件循环） | 相当于“大堂经理”，负责盯着所有任务，协调切换。 |

### 4. 适用场景
- **擅长**：**I/O密集型**任务（网络爬虫、数据库读写、文件读写、API调用）。
- **不擅长**：**CPU密集型**任务（大量数学计算、复杂循环），因为计算会霸占CPU且没有`await`切换点，会阻塞所有协程。

## 二、协程的执行逻辑 (How to run)

### 1. 基础运行流程
```python
import asyncio
import time

# 1. 定义一个协程函数（模拟等外卖）
async def order_food(name):
    print(f"🍔 正在等 {name} 外卖...")
    # 2. 遇到 await：主动让出控制权，去干别的，等待 3 秒后返回
    await asyncio.sleep(3)  # asyncio.sleep 模拟网络耗时，而不是 time.sleep
    print(f"✅ {name} 外卖到了！开吃！")
    return f"{name} 真好吃"

# 3. 定义主协程（调度中心）
async def main():
    # 创建多个任务（同时点三份不同外卖）
    task1 = asyncio.create_task(order_food("黄焖鸡"))
    task2 = asyncio.create_task(order_food("沙县小吃"))
    task3 = asyncio.create_task(order_food("兰州拉面"))
    
    print("🕐 点完单了，我看看手机...")
    
    # 等待所有外卖都送到
    results = await asyncio.gather(task1, task2, task3)
    print(f"所有外卖到齐了：{results}")

# 4. 启动运行
if __name__ == "__main__":
    start = time.time()
    asyncio.run(main())  # 这是协程的入口，必须用它来启动
    print(f"总共耗时：{time.time() - start:.2f}秒")
```
### 2. asyncio.gather 的作用
- 功能：将多个协程任务打包成一个“任务组”。
- 特性：并发执行组内所有任务，总耗时约等于耗时最长的那个任务（而非总和）。
- 返回：按传入任务的顺序（而非完成顺序）返回结果列表。

### 3. 执行顺序
> 执行A -> 遇到await，A挂起 -> 切换执行B -> 遇到await，B挂起 -> 切换执行C -> 遇 > 到await，C挂起。
> 
> 此时所有任务都挂起，事件循环进入阻塞等待。哪个任务先结束等待，就被先唤醒执行await后 > 面的代码。
> 如果后面还有其他任务就继续执行其他任务代码，执行中除非遇到await或者当前方法结束，才能执行已经有结果的

## 三、协程的切换逻辑
### 1. 协作式(非抢占性) vs 抢占式
> 1. 首先了解一下栈：
>
>     栈是先进后出，后进先出的结构（类似于往弹夹里面压子弹），方法执行时是入栈。
>     - 当一个方法A执行，就表示方法A入栈
>     - 当执行A的中途，又执行方法B，方法B入栈
>     - 当方法C执行，方法C入栈
> 
>     此时是A--->B--->C的入栈顺序，执行时出栈（结束顺序就是）C-->B-->A
> 2. 队列则是先进先出，后进后出，类似于排队不过方法执行一般不是队列方式，协程则是一种
> 形式上的队列方式

了解完基础知识后，我们来看协程执行的特性：**非抢占性**

- 线程（抢占式）：  
操作系统拥有控制权，时间片一到强行中断。  
线程执行时，一旦时间片用完，不管执行到哪里，什么状态，有没有完成，操作系统都直接把cpu剥夺，给下一个线程使用
- 协程（非抢占式）：  
程序员/代码拥有控制权，主动让出（await）才能切换。  
方法执行时，只有是方法执行完毕，遇到await两种情况下，才会主动让出执行权，哪怕其他程序已经执行await结束，再怎么通知事件循环，也带等当前正在执行的方法主动让出执行权才能继续执行（指的就执行结束或是遇到await主动让出执行权）

**调度的铁律**：谁先结束等待，谁先被处理（先进先出原则），但前提是当前正在运行的协程必须主动让出 CPU。

### 2. 切换的完整底层流程
1. 事件循环从就绪队列头部取出一个协程（如A）。
2. 执行A，直到遇到 await。
3. A挂起：保存当前执行状态（书签），将A移入“等待列表”，并注册闹钟（如3秒）。
4. 事件循环立刻从队列头部取出下一个任务（如B）继续执行。
5. 当A的等待时间到了（闹钟响），事件循环将A重新放回就绪队列的尾部。
6. 等到队列前面的任务执行完，轮到了A，事件循环读取之前保存的书签，从 await 的下一行继续执行。

### 3. 异步的本质
当耗时任务有返回值时，它并不会“立即转头”处理，而是乖乖去队列末尾排队。必须等到当前协程主动让出（await/结束），并且轮到这个任务出队（即队列头部是它）时，才会执行后面的逻辑。

注意这里如果当前协程之后还有协程未执行，例如协程是A,B,C,D
这里C让出执行权之后，会先看一眼就绪队列里面是否有已经返回结果的协程，如果有则先执行协程中的方法，最后再处理后续的协程D
