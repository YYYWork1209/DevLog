# 悲观乐观锁对比
|类型|思想|实现|
|---|---|---|
|悲观锁|操作时别人肯定会乱改，先上锁|先加锁再操作|
|乐观锁|操作时别人可能会乱改，我最后检查一下|版本号/CAS|
---
## 悲观锁
一种思想，认为会发生冲突，所以先加锁。
```markdown
悲观锁思想
    │
    ├── 数据库行锁（悲观锁的一种实现）
    │       └─ SELECT FOR UPDATE / LOCK IN SHARE MODE
    │
    ├── 分布式锁（悲观锁的一种实现）
    │       └─ Redis / ZooKeeper / etcd 实现
    │
    └── 本地锁（单 JVM 内）
            └─ synchronized / ReentrantLock

```

**分布式锁和行锁和本地锁都是"悲观锁思想"的具体实现**，但分布式锁能跨服务，行锁只能单库。
```markdown
悲观锁 = 一种思想（认为会冲突，先锁）

分布式锁 = 悲观锁思想 + 跨进程实现（Redis/ZK）
行锁      = 悲观锁思想 + 单 DB 实现（SQL）
本地锁    = 悲观锁思想 + 单 JVM 实现（Java）

它们核心思想一样，但实现不同决定了使用场景不同。

```

### 本地锁，数据库行锁，分布式锁的区别
|类型|作用范围|是否跨JVM|实现|
|---|---|---|---|
|本地锁|单JVM内|否|synchronized/ReentrantLock|
|数据库行锁|单DB（数据库）实例内部|否|SELECT FOR UPDATE|
|分布式锁|多节点/多服务|是|Redis/ZooKeeper|
